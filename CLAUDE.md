# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What is this repository

**Orquestrum** is a multi-agent Specification-Driven Development (SDD) framework. It defines orchestrator agents, specialized sub-skills, and governance documentation that together guide a software project through a structured pipeline of phases (-1 to 5).

This repository is the **canonical source** of the framework. The files here do not run directly in projects — they are converted to each tool's format and installed in target projects via the `orquestrum` CLI (`orquestrum convert` + `orquestrum install`).

---

## Commands

```bash
# Validate all agents and skills (zero references to tool-specific paths)
orquestrum lint

# Generate integration packages (no provider — model not set, user chooses at runtime)
orquestrum convert --all
orquestrum convert --tool opencode

# Choose a provider — models are resolved and locked in the generated agents
orquestrum convert --all --provider claude    # anthropic/claude-*
orquestrum convert --all --provider copilot   # github-copilot/claude-*
orquestrum convert --all --provider glm       # zai-coding-plan/glm-*

# Install a generated package in a target project
orquestrum install --tool claude-code --target /path/to/project
orquestrum install --tool opencode --target ~/.config/opencode   # global (recommended)
orquestrum install --auto --target /path/to/your/project        # detects installed tools

# Install external dependencies (agency-agents, anthropics/skills)
orquestrum deps --target ~/.config/opencode
orquestrum deps --target ~/.config/opencode --only agency   # agency-agents
orquestrum deps --target ~/.config/opencode --only skills   # anthropics/skills (includes supabase)

# Run the MCP server (stdio — meant to be spawned by Claude Code / opencode)
orquestrum mcp                                              # see docs/governance/MCP.md
npx @modelcontextprotocol/inspector orquestrum mcp          # interactive inspector
```

> Always run `orquestrum lint` before `orquestrum convert`. Lint fails with exit 1 on errors.

## Architecture

### Directory structure

```
agents/       ← 8 orchestrator agents (canonical source)
skills/       ← 25 specialized sub-skills (each: SKILL.md + assets/ + references/)
docs/
  agent-context/  ← read by LLMs at runtime (SDLC, TIERS, CONVENTIONS)
  governance/     ← read by humans (MODELS, COST, ROADMAP, HOOKS, …)
  baselines/      ← auto-generated audits
orquestrum/   ← Python package: cli.py + commands/ (subcmd handlers) + core/ (logic) + lib/ (shared) + mcp/ (MCP server)
ui/           ← FastAPI web console (see ui/README.md)
integrations/ ← Generated by `orquestrum convert`; one subdir per tool (do not edit manually)
bundle/       ← stand-alone shell helpers (e.g. archive-cleanup.sh)
```

### Path convention in canonical source

Agents and skill assets always use **paths without tool-specific prefixes**:
- `docs/agent-context/SDLC.md` — governance reference
- `docs/agent-context/CONVENTIONS.md` — shared conventions (context fence, naming, output format)
- `skills/<name>/SKILL.md` — references to other skills
- `./references/`, `./assets/` — internal references within a skill

`orquestrum convert` (logic in `orquestrum/core/convert.py`) rewrites these paths for each tool:
- Claude Code / Cursor / Aider / Windsurf: `docs/` → `.sdd/docs/`, `skills/` → `.sdd/skills/`
- OpenCode: `docs/` → `__OPENCODE_ROOT__/docs/`, substituted with the absolute target path at install time

### Pipeline phases

| Phase | Agent | Delegated skills |
|-------|-------|-----------------|
| -1 Onboarding | `Trace - Onboarding Lead` | codebase-mapper → reverse-spec → adr-manager → glossary-manager |
| 0–1 Discovery | `Lore - Product Strategist` | discovery-manager (or glossary-manager → spec-manager separately) |
| 1 Decisions | `Lore - Product Strategist` | adr-manager → pattern-manager |
| 2 Design | `Forge - Dev Lead` | pattern-manager → architecture-manager |
| 3 Planning | `Forge - Dev Lead` | epic-manager → task-manager |
| 3.5 Security | `Cipher - Security Lead` | security-manager |
| 4 Quality | `Ward - Quality Lead` | review-manager → qa-manager → learning-manager |
| 5 Release | `Cast - Ship Lead` | changelog-manager → runbook-manager → archive-manager |
| Maintenance | `Flux - Support Lead` | (triage + routing) |

`Helm - The Architect` is the meta-orchestrator: classifies the work tier (0/1/2) and decides which agent to invoke and which gates to validate. `Forge - Dev Lead` can also operate as primary for Tier 0 work (fast-path without Helm routing).

### Work tiers

The tier defines which phases and artifacts apply:
- **Tier 0** (Micro): Task + Log (~2 LLM calls)
- **Tier 1** (Standard): Epic + Task + Log + QA (~5 LLM calls)
- **Tier 2** (Full): Complete pipeline (~13 LLM calls)

Critical rule: **refactoring never elevates by file count** — only elevates to Tier 2 if it introduces a new architectural decision.

### Agent structure (`agents/*.md`)

```yaml
---
name: Agent Name
description: One-line description
mode: primary | agent
temperature: 0.1
emoji: 🏛️
tools:
  write: true
  edit: true
  bash: false
  question: true
---
```

Required fields checked by lint: `name`, `description`. Model is not set in frontmatter — see `docs/governance/MODELS.md` for tier assignments. All agents use the provider-selected model (deep/balanced/mechanical) based on their tier assignment in the convert step.

### Skill structure (`skills/<name>/`)

```
SKILL.md          ← complete definition: dependencies, I/O, flow, chain
assets/           ← document templates the skill produces
references/       ← reference material the skill reads before executing
```

Skills declare a `chain` field in frontmatter for automatic sequencing (e.g. glossary-manager → spec-manager → adr-manager).

### External dependencies (via `orquestrum deps`)

Use `orquestrum deps` to install external agent and skill repositories:

```bash
orquestrum deps --target ~/.config/opencode           # All dependencies
orquestrum deps --target ~/.config/opencode --only agency   # agency-agents
orquestrum deps --target ~/.config/opencode --only skills   # anthropics/skills
```

**Installed dependencies:**
- **agency-agents** (msitarzewski/agency-agents) — 184+ specialized agents
- **anthropics/skills** — 17 skills including Supabase integration
- **supabase/agent-skills** — Skipped (already included in anthropics/skills)

> Note: `deps` clones to temporary directories and does not pollute the Orquestrum repository.

## OpenCode integration specifics

OpenCode uses flat agent files. The **filename without `.md`** is the official `subagent_type` used by the Task tool.

### All agents are primary

All 8 agents are emitted as `mode: primary` — they appear in the Tab picker and can be called directly by the user or via Task tool by other agents.

| Canonical `name:` | Filename | Model tier |
|---|---|---|
| `Helm - The Architect` | `helm-the-architect.md` | deep |
| `Lore - Product Strategist` | `lore-product-strategist.md` | balanced |
| `Forge - Dev Lead` | `forge-dev-lead.md` | balanced |
| `Cipher - Security Lead` | `cipher-security-lead.md` | balanced |
| `Ward - Quality Lead` | `ward-quality-lead.md` | balanced |
| `Cast - Ship Lead` | `cast-ship-lead.md` | mechanical |
| `Flux - Support Lead` | `flux-support-lead.md` | balanced |
| `Trace - Onboarding Lead` | `trace-onboarding-lead.md` | balanced |

> Both Claude Code and OpenCode route Task calls by the agent's `name:` field (Title Case). Filenames remain kebab-case for filesystem organization only.

### Conversion behavior

- **Without `--provider`**: `model` field is omitted from frontmatter — user chooses model at runtime
- **With `--provider`**: `model` field is set based on the agent's tier and the selected provider
- Helm has restricted `permission.task` (only the 7 orchestrators); all others use `"*": allow`
- Agency-agents (from [msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents)) are callable by all non-Helm agents

### Output structure (`integrations/opencode/`)

```
agents/
  helm-the-architect.md
  lore-product-strategist.md
  forge-dev-lead.md
  cipher-security-lead.md
  ward-quality-lead.md
  cast-ship-lead.md
  flux-support-lead.md
  trace-onboarding-lead.md
docs/        ← SDLC.md, TIERS.md, MODELS.md, CONVENTIONS.md
skills/      ← reference documentation (read as files by orchestrators)
```

**Skills remain as documentation** (not registered as OpenCode agents). Orchestrators read `__OPENCODE_ROOT__/skills/<name>/SKILL.md` at runtime and follow the workflow instructions inline.

## Adding a new agent or skill

1. Create the file with valid frontmatter (fields: `name`, `description`)
2. Use only canonical paths in the body (`docs/`, `skills/`, `./references/`, `./assets/`)
3. Run `orquestrum lint` — must pass with zero errors
4. Run `orquestrum convert --all` to update `integrations/`
5. **If adding a new agent:** the kebab-case name is computed automatically from the `name:` field by `name_to_kebab()` in `lib/paths.py`. No manual changes needed.
6. **If adding a new skill:** it remains as documentation (not an OpenCode agent). No changes to `convert.py` are needed.
