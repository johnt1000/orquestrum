# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What is this repository

**Orquestrum** is a multi-agent Specification-Driven Development (SDD) framework. It defines orchestrator agents, specialized sub-skills, and governance documentation that together guide a software project through a structured pipeline of phases (-1 to 5).

This repository is the **canonical source** of the framework. The files here do not run directly in projects — they are converted to each tool's format and installed in target projects via scripts.

---

## Commands

```bash
# Validate all agents and skills (zero references to tool-specific paths)
./scripts/lint-agents.sh

# Generate integration packages (no provider — model not set, user chooses at runtime)
./scripts/convert.sh --all
./scripts/convert.sh --tool opencode

# Choose a provider — models are resolved and locked in the generated agents
./scripts/convert.sh --all --provider claude    # anthropic/claude-*
./scripts/convert.sh --all --provider copilot   # github-copilot/claude-*
./scripts/convert.sh --all --provider glm       # zai-coding-plan/glm-*

# Install a generated package in a target project
./scripts/install.sh --tool claude-code --target /path/to/project
./scripts/install.sh --tool opencode --target ~/.config/opencode   # global (recommended)
./scripts/install.sh --auto --target /path/to/project   # detects installed tools
```

> Always run `lint-agents.sh` before `convert.sh`. Lint fails with exit 1 on errors.

## Architecture

### Directory structure

```
agents/       ← 6 orchestrator agents (canonical source)
models/       ← Provider profiles (profiles.sh) for --provider flag
skills/       ← 16 specialized sub-skills (each: SKILL.md + assets/ + references/)
docs/         ← Pipeline governance (SDLC.md, TIERS.md, MODELS.md, CONVENTIONS.md)
scripts/      ← convert.sh, install.sh, lint-agents.sh
integrations/ ← Generated by convert.sh; one subdir per tool (do not edit manually)
```

### Path convention in canonical source

Agents and skill assets always use **paths without tool-specific prefixes**:
- `docs/SDLC.md` — governance reference
- `docs/CONVENTIONS.md` — shared conventions (context fence, naming, output format)
- `skills/<name>/SKILL.md` — references to other skills
- `./references/`, `./assets/` — internal references within a skill

The `convert.sh` script rewrites these paths for each tool:
- Claude Code / Cursor / Aider / Windsurf: `docs/` → `.sdd/docs/`, `skills/` → `.sdd/skills/`
- OpenCode: `docs/` → `__OPENCODE_ROOT__/docs/`, substituted with the absolute target path at install time

### Pipeline phases

| Phase | Agent | Delegated skills |
|-------|-------|-----------------|
| -1 Onboarding | `trace-onboarding-lead` | codebase-mapper → reverse-spec → adr-manager → glossary-manager |
| 0–1 Discovery | `lore-product-strategist` | discovery-manager (or glossary-manager → spec-manager separately) |
| 1 Decisions | `lore-product-strategist` | adr-manager → pattern-manager |
| 2 Design | `forge-dev-lead` | pattern-manager → architecture-manager |
| 3 Planning | `forge-dev-lead` | epic-manager → task-manager |
| 4 Quality | `ward-quality-lead` | review-manager → qa-manager → learning-manager |
| 5 Release | `cast-ship-and-support-lead` | changelog-manager → runbook-manager |

`helm` is the meta-orchestrator: classifies the work tier (0/1/2) and decides which agent to invoke and which gates to validate. `forge` can also operate as primary for Tier 0 work (fast-path without Helm routing).

### Work tiers

The tier defines which phases and artifacts apply:
- **Tier 0** (Micro): Task + Log (~2 LLM calls)
- **Tier 1** (Standard): Epic + Task + Log + QA (~5 LLM calls)
- **Tier 2** (Full): Complete pipeline (~13 LLM calls)

Critical rule: **refactoring never elevates by file count** — only elevates to Tier 2 if it introduces a new architectural decision.

### Agent structure (`agents/*.md`)

```yaml
---
name: Agent Name
description: One-line description
mode: primary | agent
temperature: 0.1
emoji: 🏛️
tools:
  write: true
  edit: true
  bash: false
  question: true
---
```

Required fields checked by lint: `name`, `description`. Model is not set in frontmatter — see `docs/MODELS.md` for tier assignments.

### Skill structure (`skills/<name>/`)

```
SKILL.md          ← complete definition: dependencies, I/O, flow, chain
assets/           ← document templates the skill produces
references/       ← reference material the skill reads before executing
```

Skills declare a `chain` field in frontmatter for automatic sequencing (e.g. glossary-manager → spec-manager → adr-manager).

### Project artifacts generated (in target project, never here)

```
docs/00-discovery/glossary/GLOSSARY.md
docs/00-discovery/spec/spec-vX.md
docs/00-discovery/adr/ADR-XXX.md
docs/00-discovery/patterns/PATTERNS.md
docs/01-design/architecture/ARCHITECTURE-vX.md
docs/02-planning/epics/E{ID}.md
docs/02-planning/tasks/T{ID}.md + logs/T{ID}-log.md

docs/03-quality/learning/L-XXX.md

```

## OpenCode integration specifics

OpenCode uses flat agent files. The **filename without `.md`** is the official `subagent_type` used by the Task tool.

### All agents are primary

All 6 agents are emitted as `mode: primary` — they appear in the Tab picker and can be called directly by the user or via Task tool by other agents.

| Canonical `name:` | Display `name:` | Filename → `subagent_type` | Model tier |
|---|---|---|---|
| `Helm - The Architect` | `Helm - The Architect` | `helm-the-architect.md` | deep |
| `lore-product-strategist` | `Lore - Product Strategist` | `lore-product-strategist.md` | balanced |
| `forge-dev-lead` | `Forge - Dev Lead` | `forge-dev-lead.md` | balanced |
| `ward-quality-lead` | `Ward - Quality Lead` | `ward-quality-lead.md` | balanced |
| `cast-ship-and-support-lead` | `Cast - Ship & Support` | `cast-ship-and-support-lead.md` | mechanical |
| `trace-onboarding-lead` | `Trace - Onboarding` | `trace-onboarding-lead.md` | balanced |

### Conversion behavior

- **Without `--provider`**: `model` field is omitted from frontmatter — user chooses model at runtime
- **With `--provider`**: `model` field is set based on the agent's tier and the selected provider
- Helm has restricted `permission.task` (only the 5 orchestrators); all others use `"*": allow`
- Agency-agents (from [msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents)) are callable by all non-Helm agents

### Output structure (`integrations/opencode/`)

```
agents/
  helm-the-architect.md
  lore-product-strategist.md
  forge-dev-lead.md
  ward-quality-lead.md
  cast-ship-and-support-lead.md
  trace-onboarding-lead.md
docs/        ← SDLC.md, TIERS.md, MODELS.md, CONVENTIONS.md
skills/      ← reference documentation (read as files by orchestrators)
```

**Skills remain as documentation** (not registered as OpenCode agents). Orchestrators read `__OPENCODE_ROOT__/skills/<name>/SKILL.md` at runtime and follow the workflow instructions inline.

## Adding a new agent or skill

1. Create the file with valid frontmatter (fields: `name`, `description`)
2. Use only canonical paths in the body (`docs/`, `skills/`, `./references/`, `./assets/`)
3. Run `./scripts/lint-agents.sh` — must pass with zero errors
4. Run `./scripts/convert.sh --all` to update `integrations/`
5. **If adding a new agent:** the kebab-case name is computed automatically from the `name:` field by `name_to_kebab()` in `convert.sh`. No manual changes needed.
6. **If adding a new skill:** it remains as documentation (not an OpenCode agent). No changes to `convert.sh` are needed.
